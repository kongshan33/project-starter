# 设计资料

| 位置 | 职责 |
| --- | --- |
| `docs/` | 已接受的产品、系统、设计规范与执行规则 |
| `prototypes/` | 可交互原型、静态设计稿与其状态说明 |
| `assets/` | 可复用的设计资源，记录作者与授权 |
| `references/` | 外部灵感、参考截图；标记来源，不能自动视为已接受需求 |
| `archive/` | 被替代的设计版本，明确替代关系 |
| `docs/decisions/` | 长期决策及其理由 |

每个新设计稿记录标题、日期、状态（draft/reference/accepted/superseded）、
负责的流程、来源与对应规范。代码是实施事实；已接受文档定义预期行为。
发现差异时先明确差异，按用户当前目标处理，不静默覆盖一方。

基础组件的可运行设计稿在 Web 的 `/design-system`。它与正式规范引用同一套
`packages/ui`，避免维护第二份会漂移的 HTML 组件实现。

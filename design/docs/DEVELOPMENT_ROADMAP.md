# 新项目交付顺序

本文件规划阶段与依赖；`TASK.md` 记录当前可执行任务；`PROJECT.md` 记录实际能力。
下面是初始化后的默认顺序，不表示新项目已经完成任何阶段。按产品实际范围裁剪。

| 阶段 | 目标 | 完成证据 |
| --- | --- | --- |
| 0：初始化 | 替换项目身份、明确目标用户和第一个流程 | 新目录安装与检查通过；PRODUCT_SPEC 有可验收条件 |
| 1：最小流程 | 从界面到 API 打通一个真实本地流程 | 正常、空、等待、失败与重试状态可运行；相关浏览器验收通过 |
| 2：必要集成 | 按需求加入身份、存储或外部服务 | 数据归属和配置明确；真实集成证据与模拟测试分开记录 |
| 3：产品验收 | 完成核心任务并收敛通用 UI | 桌面、窄屏、键盘与错误恢复检查；文档反映实际行为 |
| 4：交付与接力 | 可部署、可排障、可由新 agent 继续 | 环境与回滚步骤可执行；实际部署结果单独记录；交接可复现 |

每次只展开当前阶段的任务。跨阶段的技术选择写入 DECISIONS；新增真实集成时先
阅读 OPTIONAL_MODULES。不要因模板包含某目录就推断产品需要对应功能。

阶段顺序或范围改变时更新本文件；阶段实际完成时同步 PROJECT、TASK 和交接。
